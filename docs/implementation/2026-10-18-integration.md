# MQTT・API・市区町村対応の実装・検証記録

実施日：2026-10-18（日本時間）

## 実装した内容

- UI、Controller、気象、花粉、推薦の5プログラムを分離し、HTTPとMQTTで接続した。Brokerは別プロセス。初期値は127.0.0.1で動かす。
- MQTTはQoS1/retain=false。購読完了後に送信し、検索ID・日付・場所・送信元・版・デモ状態を照合する。同時検索を分離し、重複・期限切れ返信を除外する。Workerの並行実行と重複記録は上限付き。
- Open-Meteoの日別APIを対象日・Asia/Tokyo・m/sで取得する。Google PollenのdailyInfoを対象日で照合し、植物と地域分類を分離する。キー不足・日付欠測・HTTP異常を構造化エラーで返す。
- 市区町村は国土地理院の自治体一覧を使い、同名候補を都道府県付きで区別する。現在地は逆引きで自治体を特定し、その代表地点を両APIに渡す。
- 任意の設定種の有効UPI最大で個人レベルを判定する。一部欠測は暫定、全設定種欠測は判定不可。未設定は地域分類による一般情報。風によるレベル加算はない。
- localStorageにアレルギー設定だけを保存・復元・削除する。位置・結果・キーは保存しない。再訪問では結果は復元せず、検索操作で再取得する。
- `python run.py --demo`と`python run.py`を用意し、起動順・競合ポート・子プロセス停止を扱う。READMEと.env.exampleに実行手順を記載した。
- Geminiの実呼出しは追加していない。将来の対策文生成は`assess(payload, advisor=...)`で差し替え、レベルはPythonで固定する。不正な対策文はルールへ戻す。
